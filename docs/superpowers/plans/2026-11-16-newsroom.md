# Newsroom Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An official JNVPJAA newsroom: news written by authorised editors and published under the association's name at `/newsroom`. The homepage shows the latest items, rendered on the server, and hides the section when there are none.

**Architecture:** The backend gets a new `NewsPost` table, kept separate from member blogs, plus one permission, `newsroom.post.manage`. The logic lives in a service that takes a `db` argument so tests can pass a fake database, with thin Nexus resolvers on top. On the web side, `/newsroom`, `/newsroom/[slug]`, the RSS feed and the homepage section are server components that fetch on every request (`force-dynamic`), as `/blog` already does. Editors write in a client-side manage page that reuses the blog's TipTap editor and cover picker.

**Tech Stack:**
- Backend (`jnvpjaa-backend`): Prisma, Nexus, Apollo Server 4, `node:test` via ts-node
- Web (`jnvpjaa-web`): Next 14 app router, MUI v6, Apollo Client, Tabler icons, `node:test` `.cjs` tests

**Spec:** This plan carries the spec. The user asked for a newsroom that publishes official news and updates directly on the site, follows standard newsroom practice, is loaded server-side, and shows the latest items on the homepage, with nothing shown when none exist. The decisions below are the builder's calls, made from that request.

## Decisions (builder's calls; the user can overrule any of them)

- **Separate from blogs.** News is a new `NewsPost` model, not a blog category, so official news never mixes with member posts, claps or comments.
- **Official byline.** The public byline is always "JNVPJAA Communications". The writer's identity is kept in `createdById`/`updatedById` and the activity log, and is never shown publicly.
- **Categories:**

  | Enum value | Label |
  |---|---|
  | `ANNOUNCEMENT` | Announcement |
  | `PRESS_RELEASE` | Press release |
  | `ACHIEVEMENT` | Achievement |
  | `IN_THE_MEDIA` | In the media |

  `IN_THE_MEDIA` posts may carry a `sourceUrl` linking to the outside article.
- **Status:** `DRAFT` or `PUBLISHED`. There is no approval queue, because only trusted editors can write news.
- **Scheduling comes from `publishedAt`.** A published post with a future `publishedAt` stays hidden everywhere public until that time. No cron job is needed.
- **Pinning:** `isPinned` puts a post first in the list as the lead story.
- **Corrections:** an optional `updateNote` (e.g. "Corrected the event date") is shown as "Updated <date>: <note>". Public pages show "Updated" only when the note is set.
- **Who can publish:** the new permission `newsroom.post.manage` is granted to:
  - Platform Admin
  - President
  - Secretary
  - Super Admin (automatically, since it holds every permission)
- **Homepage section:** "From the newsroom" shows up to 3 items, placed after `MetricsNumbers`. If there are none, or the API call fails, the section is not rendered at all.
- **Included standards:**
  - dateline ("JAIPUR, 16 Nov 2026 —")
  - `NewsArticle` JSON-LD
  - Open Graph tags
  - entries in the sitemap
  - RSS feed at `/newsroom/feed.xml`
  - press-contact box linking to `/contact-us`
- **Non-goals:** media kit/logo downloads, an approval workflow, comments, claps, per-post analytics, email or social auto-posting.

## Global Constraints

- Public reads never return `DRAFT` posts or posts whose `publishedAt > now()`. This applies to the list, the detail page, the homepage, the sitemap and RSS.
- Every write calls `authorize(ctx, PERMISSION_CODES.NEWSROOM_POST_MANAGE)` from `src/services/accessControl.ts`.
- Content is stored and returned through `sanitizeHTMLInput` from `@/utils`. `sourceUrl` must be `https://`.
- Field limits:
  - `title`: 5–160 characters
  - `summary`: required, 20–300 characters
  - `updateNote`: 200 characters at most
- Slugs come from `generateSlug(title, 'news')` in `src/utils/blog.ts`. On a clash, append `-2`, `-3`, and so on.
- Public list order: `isPinned desc, publishedAt desc`. The public `limit` is capped at 50.
- The migration is additive only (new enums and a new table).
- The web app must keep working if the newsroom query fails. Pages show an empty state; the homepage omits the section.

## Review Focus

1. **A scheduled post leaks early.** A post that is `PUBLISHED` with `publishedAt` tomorrow must not appear in the list, the detail page, the homepage, the sitemap or RSS. Tested in Task 2 (`hides scheduled posts`) and Task 3 (`sitemap skips scheduled news`).
2. **The API is down while the homepage renders.** The homepage must render without the news section, not show an error page. Tested in Task 6 (`latestNews returns [] on error`).
3. **A member without the permission calls `saveNewsPost` directly.** The call must be rejected with "Permission denied" and nothing written. Tested in Task 2.
4. **Two posts share a title, or a title is in Hindi.** Each post gets a unique, readable slug. Tested in Task 2 (`unique slug on clash`, `keeps Hindi slug`).
5. **Script injection.** `<script>` in the content and `javascript:` in `sourceUrl` must be stripped or rejected. Tested in Task 2.
